Reading the canvas

What the numbers on each node mean

Cost and time per run

Each node shows its expected cost and time for one run of the system, weighted by how often its branch is taken. A node inside a loop is multiplied by the expected iterations.

p50 and p95

p50 follows the most likely branch at each router with the expected loop count. p95 follows the most expensive branch with the maximum loop count. If a loop has no exit, p95 is unbounded.

Prices are illustrative

Model tiers use made-up per-token prices so the arithmetic is visible. In the real product, forecasts are calibrated against the system's own traces after its first runs.

The graph is code

"View as code" shows the spec the canvas edits. A team can write the same spec by hand, review it in a pull request and run the same pre-flight in CI.

Checkpoints are automatic

By default the runtime saves state at every node boundary. The System tab lets a team change that, and pre-flight objects if a graph waits for people with checkpoints off.

Not shown in this prototype

Sub-graphs, versions and diffs, collaborative editing, and live overlays of real trace data on the nodes. The Run page shows what that overlay would look like.
