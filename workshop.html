Change safely · Workshop

Copy a live system into a sandbox, change it, test it, ship a pull request

The Workshop is where a team changes an agent system it already runs: new tools, skills, agents, an orchestrator, memory, a bigger golden set. Pre-flight comments on every edit. Tests climb from replays to real sandbox systems. The result goes back to the team's own repo as a pull request, in the team's own framework. Trellis does not host it unless the team wants that.

The flow

Five steps from idea to pull request

Copy

Copy the live system into a sandbox, like a Git branch. Sandbox credentials only. Nothing can write to production.

Change

Edit on the canvas or in code. Both change the same graph spec, plus skill files, prompts and datasets.

Check

Pre-flight runs on every edit: errors, warnings, cost and latency change.

Test

Climb the test ladder: replays, fakes, real sandbox systems, shadow traffic.

Ship

Open a pull request in the team's repo, in their framework's format. They deploy it as they do today.

The test ladder

Recordings for every edit, real sandbox systems before merge

Recordings and real sandboxes are not a choice. Each rung is more realistic and slower than the one below it, so cheap rungs run on every edit and real ones gate the pull request. Select a rung, then run it against the session above.

What real sandbox systems cost

Someone has to provision them, keep the data fresh and mask personal data in copies. Real third-party sandboxes can be slow and flaky. Trellis provisions each one per Workshop session and tears it down afterwards, so these costs are paid once per test run, not on every edit.

Ship it back

Graph to code: reuse each framework's own format

No existing tool turns one canvas into clean code for every framework. Several frameworks already load a declarative file, though, and visual tools already run their own JSON. So Trellis writes each framework's native format where one exists and generates code from templates only where it must. Pick the team's framework.

Pull request · support-triagepre-flight passed

Framework formats change quickly. Check each one against its current release before building an exporter. "Round trip" means Trellis can also read the team's edits back into the graph.

Creating tools

Integrate tool builders that already exist. Do not write our own.

Trellis adds a contract, a risk tier, policy and tests to each tool. The tool itself comes from services that already do this well. All of them produce or speak MCP, so a new tool reaches every framework the same way.

Where it fits

A feature of the same platform, built in steps

The Workshop reuses everything else in Trellis: the spec, the catalog, pre-flight, evals, the gateways and checkpoints. As a separate product it would have to rebuild all of them.
