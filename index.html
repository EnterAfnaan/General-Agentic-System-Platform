Trellis Agent Studio

Concept prototype · Agentic systems across teams · October 2026

Know what an agent system will do, cost and be allowed to touch before it runs.

Trellis is a shared workbench for agentic systems. Teams connect their data and tools once, compose agents and coding harnesses on a canvas, get a pre-flight check before anything runs, and improve the system from its own runs. It sits above the frameworks teams already use. It does not replace them.

The loop

Four stages that repeat, one entry point, one frame around all of it

Connect is done once per integration. Compose, Check, Run and Learn repeat for the life of a system. Governance is not a stage: policy is attached to the graph and enforced at every step. Select a stage to see what it does.

Why bother

What teams building agents live with today

Each team picks a framework, wires its own connectors, writes its own approval step and finds out what the system costs from the monthly bill. None of these problems is about model quality. They are all about the missing layer around the agents.

Every team rebuilds the same plumbing

Database access, retries, human approval, secrets and tracing get rebuilt in LangGraph by one team, Microsoft Agent Framework by another and a shell script by a third.

Symptom: 4 approval implementations, none audited the same way

Cost and latency show up in production

A loop that usually runs 3 times runs 14 times on a hard case. A context window grows by the full tool output on every turn. Nobody saw it on a whiteboard.

Symptom: a $0.04 run becomes $1.90 on the long tail

Governance is per team and uneven

One team redacts personal data before calling an external model. Another sends raw tickets. A coding harness runs with network access because no one decided otherwise.

Symptom: no single answer to "what can our agents write to?"

Nothing learns from its own runs

Thumbs-down feedback is stored and never read. A fix one team finds for a prompt or a tool sequence never reaches the team with the same problem.

Symptom: runs are logged, but never turned into evals

Three systems, three shapes

The examples used throughout these pages

Each comes from a different team and has a different structure. If one workbench handles all three well, the idea holds up across teams.

Customer Support

Support triage

Router workflow. Redact, classify, retrieve from the knowledge base, draft a reply. Refunds over a limit need a person to approve.
Platform Engineering

PR review

Parallel goals. Claude Code checks correctness, Codex writes missing tests, a security agent scans the diff. One agent merges findings into a single comment.
SRE / Database reliability

Incident investigator

Goal-based loop. Recall similar past incidents, propose hypotheses, test them one at a time with read-only queries, stop when one is confirmed or the budget runs out.

People

Who uses Trellis, and for what

B

Builder

AI engineer or developer. Composes the graph, writes code nodes, reads pre-flight findings, runs evals.

L

Team lead

Owns the budget and the outcome. Reads the forecast, the rating and the monthly spend per system.

A

Approver

Support supervisor, senior engineer or DBA. Gets an approval request in Teams or Slack with the evidence and the exact action.

P

Platform and security admin

Writes org-level policy once: data classes, model boundaries, write tiers, budgets. Reviews exceptions.

C

Consumer

A person or another agent calling the system over chat, an API, MCP or A2A. Never sees the graph.

The bet

Start with the pre-flight check, not the canvas

A canvas alone is a commodity. A check that reads any team's agent graph and says "this loop has no exit, this refund has no approval, this step will cost $1.90 on bad days" is new, and it works on systems teams already have.

It needs no migration

Import an existing LangGraph or Agent Framework graph into the spec and run the check. Teams get value on day one without moving their runtime.

It makes the rest possible

The typed graph spec that the check needs is the same thing the canvas edits, the gateways enforce and the learning loop improves.

It is easy to measure

Count findings caught before production and compare forecasts with actual cost. Both are numbers a lead or a manager will read.
