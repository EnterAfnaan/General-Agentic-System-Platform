Across every stage · Govern

Policy is part of the graph, and it is enforced at the edges

Platform and security teams write policy once. Every system inherits it. Pre-flight checks it at design time, and three gateways enforce it at run time, whatever framework or harness made the call. Agents never hold credentials for the systems they touch. The gateways do.

Where enforcement happens

Every model call, tool call and data read passes a gateway

This is what makes governance work across frameworks. A LangGraph agent, an Agent Framework workflow and Claude Code all reach models and tools through the same three doors, so the same rules apply to each.

The honest limit

A harness running in a sandbox can still reason badly inside it. Trellis controls what leaves the sandbox: network egress, file scope, tool calls through the MCP gateway, and spend. It cannot inspect each thought.

Policy layers

Four layers. Lower layers can tighten, never loosen.

A team cannot opt out of an org rule. It can file an exception that names an owner, a reason and an expiry date, and the exception is audited like any other change. Select a layer to see an example.

Guardrails

          
Guardrails are nodes, so they show up in the forecast

          
Each guardrail has a cost, a latency and a failure behaviour, the same as any other node. Teams can see what safety costs instead of guessing.

        

        

          
On input

            
PII detection and redaction
Finds names, emails, card and account numbers and replaces them with stable tokens that can be restored downstream.
+120 ms<$0.001redact

            
Injection screen
Classifies text from outsiders for embedded instructions before it reaches a node that can act.
+150 ms<$0.001quarantine

            
Topic and scope limits
Rejects requests outside the system's declared purpose, such as legal advice from a support bot.
+90 msrefuse politely

          

          
On output

            
Groundedness check
Every claim in a customer reply must be supported by a retrieved passage, or the reply goes back for another draft.
+900 ms$0.004redraft once

            
Output schema
Structured outputs are validated against a JSON schema before any downstream node reads them.
+5 msretry with error

            
Secret and leakage scan
Blocks keys, connection strings and internal hostnames from leaving in a reply or a PR comment.
+40 msblock

          

          
On action

            
Tool allowlist and argument checks
An agent can call only the tools in its grant, with arguments that match the schema and value limits, such as refunds up to $500.
+3 msblock

            
Read-only by default
Database connections open with read-only roles. A write needs a tier, a grant and usually a person.
0 msblock

            
Spend caps and circuit breakers
Per run, per system and per team. When a cap trips, runs stop cleanly and the owner is paged.
0 msstop run

Approval fatigue is a signal, not a nuisance
When approvers say yes to 412 of 415 small refunds, Trellis proposes a policy change on the Learn page: auto-approve below $20 for verified customers. The policy owner decides. Trellis never relaxes a rule by itself.

      


      

        

          
Identity and audit

          
Every action has an owner and a record

        

        

          

            
Each system has its own identity
A workload identity per system and environment, with only the grants its graph needs. No shared service account across teams.

            
On behalf of the user, where there is one
When a person starts a run, reads use their token, so row-level security and document permissions still apply to what the agent sees.

            
Kill switches at three levels
Pause one system, every system in a team, or all agent writes across the org. Paused runs keep their checkpoints and can resume.
