Stage 1 · Connect

Everything a system can touch becomes a typed node

A team connects a database, a vector index, a Kafka topic, an MCP server or a coding harness once. From then on it appears on the canvas as a node that declares what it can do, what data it can emit, what it costs and who may use it. Those declarations are what make the pre-flight check possible.

The node contract

Seven fields every connector declares

Without a contract, a connector is just a URL and a secret. With one, Trellis can tell you before you run that a write has no approval, that a ticket's personal data is about to reach an external model, or that a step will take 9 seconds at p95.

capabilities
What the node can do: read, write, stream or execute. Writes carry a risk tier from 1 (a comment) to 3 (money moves, data is deleted).
emits
The data classes its output can contain: public, internal, confidential, PII, secret. These labels flow along graph edges.
boundary
Where data goes when this node is called: inside our tenant, a contracted processor, or the public internet.
cost
Per call, per token, per session or per GPU-hour. Pre-flight multiplies it through loops and fan-out.
latency
p50 and p95 per call. Calibrated from real traces once the node has run.
auth
Managed identity, OAuth on behalf of a user, or a vaulted key. Never a secret pasted into a node.
defaults
Policy the owner attaches: rate limits, timeouts, retries. Org policy adds the rest: tier 3 writes always need a person, tier 2 writes need a person or an output check.
Example · refunds API, owned by Customer Support 
connector: refunds-api
kind: tool            # HTTP, described by OpenAPI
owner: team/customer-support
capabilities:
  - read: refund_status
  - write: issue_refund
    risk_tier: 3        # money moves
emits: [internal, pii]
boundary: tenant
cost: { per_call_usd: 0.0004 }
latency_ms: { p50: 420, p95: 1300 }
auth: managed_identity
defaults:
  timeout_s: 10
  retries: { max: 2, on: [429, 503] }
  approval: { required_when: "risk_tier >= 3" }  # org rule
  rate_limit: 30/min

Bring your own agent

Teams keep their frameworks. Trellis wraps them.

Nobody is asked to rewrite a working agent. There are four ways in, and each tells Trellis a different amount about what is inside.

Import a graph

LangGraph, Agent Framework workflows

An adapter reads the framework's graph definition and converts it into the Trellis spec. Every inner node becomes visible and checkable.

Glass box
MCP server

Expose tools

Any MCP server becomes a set of tool nodes. Trellis reads tool names, schemas and annotations such as read-only and destructive.

Grey box
A2A agent card

Call a remote agent

A remote agent publishes its skills and auth needs. It becomes one node with declared inputs and outputs. Its insides stay private.

Grey box
Harness or container

Claude Code, Codex, any job

Runs in a Trellis sandbox with a workspace, a goal, an allowed tool list and a budget. Trellis controls the boundary, not the reasoning inside.

Black box

An honest limit

What pre-flight can check depends on what a node shows

A coding harness decides its own steps, so nobody can lint them in advance. What Trellis can do is control everything at its edges: what it can read, where it can send data, what it can write and how much it can spend.

inner graph visible

Glass box

Native Trellis graphs and imported framework graphs.

  • Every lint rule applies, inside and out
  • Forecast per inner node
  • Traces map to inner nodes
tools and skills declared

Grey box

MCP servers, A2A agents, CrewAI crews.

  • Rules on declared tools and data classes
  • Forecast from observed calls
  • Gateway enforces tool allowlists

Claude Code, Codex, containers.

  • Budget and time caps
  • All tool calls go through the MCP gateway

Credentials and ownership

Who owns a connection, and how it stays healthy

Secrets stay in the vault

Nodes reference a secret by name. A graph spec never contains a key, so specs can be shared and reviewed in pull requests.

Scoped per team

A connection belongs to a team. Another team can request access, which creates an audit record and inherits the owner's defaults.

Agent identity, not a shared login

Each system runs as its own workload identity. Reads on behalf of a user use that user's token, so row-level security still applies.

Health and drift

Connections are probed every few minutes. If an MCP server changes a tool schema, every graph using it is re-checked and owners are told.
