Stage 3 · Check

Pre-flight: find the problems before the first run

A compiler reads code and refuses to build it if the types do not line up. Pre-flight does the same for an agent system. It reads the graph and the contracts of every node, then reports what will break, what it will cost and how safe it is. This is the part of Trellis that few tools offer today, and the one to build first.

What you get

Three outputs from one pass over the graph

1 · LintFindings

Errors block promotion beyond dev. Warnings need an owner's sign-off. Suggestions are optional. Every finding names the node, the reason and a fix that can be applied in one click.

2 · ForecastCost & time

Per run and per month, at p50 and p95, with human wait reported separately. Estimated from contracts at first, then calibrated against the system's own traces.

3 · Rating0–100

A weighted score across safety, data protection, reliability, cost, quality and observability. It helps teams compare systems and track progress. It never replaces the error gate.

It runs in four places

  • On the canvas, on every edit, as on the Compose page.
  • In the terminal with trellis preflight, for teams who write the spec by hand.
  • In CI as a required check on any pull request that changes a graph, a prompt or a policy.
  • On drift. When a connector changes a tool schema, a model is retired or org policy tightens, every affected graph is re-checked and its owner is told.

Forecast simulator

What an investigation loop will really cost

This simulates 2,000 runs of a loop like the incident investigator. Each run draws its iteration count and token use at random. Move the controls and watch the long tail. The average is rarely the number that hurts.

Cost per run across 2,000 simulated runs
Static estimate vs calibrated

Before a system runs, the forecast uses declared token counts and wide uncertainty. After a few hundred runs Trellis fits the real distributions from traces, so the band narrows. Usually the mean moves too, because declared numbers tend to be guesses.

Limits

What pre-flight cannot promise

Pre-flight is a gate, not a guarantee. It checks structure and declared contracts. These four things still need runtime guardrails and evals:

What the model decides

A graph can be well formed and still produce a wrong answer. Quality comes from evals, not lint.

Steps inside a harness

Claude Code and Codex pick their own steps. Pre-flight controls their boundary, not their plan.

Data-dependent loops

How many passes a hard case needs is only known from runs. The forecast gives a band, then calibrates it.

New attacks

An injection screen catches known patterns. Least privilege and approvals limit the damage when it misses.
